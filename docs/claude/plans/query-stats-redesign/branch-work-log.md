# Branch Work Log — `query-stats-redesign`

## Phase 1: Core Collector, Latency Histograms, and Async Context Propagation
- Rewrote `cpp/arcticdb/toolbox/query_stats.hpp` and `cpp/arcticdb/toolbox/query_stats.cpp` with a single relaxed-atomic `is_active()` fast path and zero Folly/ankerl headers in the public header.
- Implemented compact 114-bucket binary-octave log-linear `LatencyHistogram` (nanosecond precision, exact min/max/mean/percentiles, `merge()`, `diff()`).
- Implemented thread-local `QueryStatsCollector` (`folly::ThreadLocal` with retired-thread flush and strict lock ordering), nestable `CollectorSession` (with optional `isolate`), `ContextTagScope`, and `CapturedContext`/`RestoredContextGuard` over `folly::RequestContext`.
- Added library attribution (default on) and opt-in symbol attribution (`by_symbol=false` default) with `max_symbols` cap spilling into `"__other__"` and a fixed 256-byte `DroppedSymbolFilter`.
- Propagated `CapturedContext` across `TaskScheduler` CPU and IO thread pools (`cpp/arcticdb/async/task_scheduler.hpp`).
- Preserved 100% backward compatibility for the legacy `QueryStats` global singleton API (`qs.query_stats()` / `get_query_stats()`).
- Added C++ core unit tests in `cpp/arcticdb/toolbox/test/test_query_stats.cpp`.
