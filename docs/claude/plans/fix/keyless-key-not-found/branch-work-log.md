# fix/keyless-key-not-found

- With `S3.Async=1`, a missing key made `do_async_read_impl` call `raise_s3_exception`, which throws a `KeyNotFoundException` built from a message only, so `keys()` dereferenced a null `shared_ptr`. `recurse_index_keys` (ignores missing keys during prune/delete) calls `e.keys()` and segfaulted.
- Fix at the source: the async read now mirrors the sync read (`raise_if_unexpected_error`, then `throw KeyNotFoundException(unencoded_key)`), so every read-path `KeyNotFoundException` carries its key again. Guarding the callers was rejected: `iterate_snapshots` needs the key to decide whether to swallow the error, so a keyless exception cannot be handled correctly there.
- Tests: gtest `S3StorageFixture.test_async_read_missing_key_in_exception` (mock S3 client) and pytest `test_delete_with_missing_index_key_s3_async` (moto S3, prune and delete_version). Both segfaulted before the fix.
- Review follow-up: extracted `raise_read_error` so the sync and async reads share the check, the missing-key log line (respecting `dont_warn_about_missing_key`) and the keyed throw; the async path now reports the S3 object path for unexpected errors. Added an async throttling case to the gtest.
- Split the async unexpected-error check into `test_async_read_unexpected_error`, asserting the message names the S3 object path (fails on the first commit, passes after the follow-up).
- Hardening: a `KeyNotFoundException` built from a message now has an empty key list, so `keys()` no longer assumes the exception carries keys. `iterate_snapshots` rethrows a keyless exception instead of treating it as its snapshot having been deleted. Gtests: `KeyNotFoundException.keys_is_empty_when_built_from_message`, `IterateSnapshots.RethrowsKeyNotFoundWithoutKeys`, `IterateSnapshots.IgnoresKeyNotFoundForVisitedSnapshot`.
- Mongo reads now carry the missing key on the NoSuchKey/KeyNotFound server-error path (gtest `MongoMockStorageTest.TestReadNoSuchKeyCarriesKey`), so `iterate_snapshots` still ignores a snapshot deleted while iterating on Mongo.
- `iterate_snapshots` and `generate_segments_from_keys` rethrow the original exception (`throw;`) instead of building a new one, keeping its message. `storage_exceptions.hpp` is now self-contained.
